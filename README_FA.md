# Persian LLM Eval — بنچمارک فارسی برای مدل‌های زبانی

**[English README](README.md)**

این پروژه می‌سنجد که مدل‌های زبانی بزرگ (Claude، GPT و بقیه) چقدر **فارسیِ
ایرانی** را خوب می‌فهمند و به کار می‌برند. فقط دانش عمومی و ترجمه سنجیده
نمی‌شود؛ کارهایی هم هست که یک کاربر ایرانی واقعاً از دستیار هوش مصنوعی
می‌خواهد: نوشتن نامه‌ی اداری، درست کردن متنی که با کیبورد انگلیسی تایپ شده،
تبدیل تاریخ شمسی، نوشتن مبلغ چک به حروف، فهم تعارف، و بازی‌های زبانی
فارسی.

همه‌چیز متن‌باز است: سوال‌ها، کد اجرا و امتیازدهی، و نتیجه‌ی هر مدل همراه با
جواب‌هایش.

## تازه‌ترین نتایج (مهر ۱۴۰۵)

Claude Opus 5.5 و Claude Sonnet 5.5 با چند سطح «فکر کردن» روی هر ۵۴۴ سوال:

| تنظیم | کاربردی | چالشی | سخت | عمومی | میانگین | هزینه (دلار) |
|---|:---:|:---:|:---:|:---:|:---:|---:|
| Opus 5.5 · low | **۰٫۹۵۷** | ۰٫۸۸۰ | **۰٫۸۹۷** | **۰٫۹۲۷** | **۰٫۹۱۵** | ۰٫۹۱ |
| Opus 5.5 · medium | ۰٫۹۵۰ | **۰٫۸۹۰** | ۰٫۸۷۳ | ۰٫۹۲۵ | ۰٫۹۱۰ | ۱٫۱۰ |
| Opus 5.5 · high | ۰٫۹۴۴ | ۰٫۸۷۰ | ۰٫۸۸۸ | ۰٫۹۲۴ | ۰٫۹۰۶ | ۱٫۱۷ |
| Sonnet 5.5 · بدون فکر | ۰٫۸۷۹ | ۰٫۷۵۰ | ۰٫۸۵۶ | ۰٫۸۹۶ | ۰٫۸۴۵ | ۰٫۳۱ |
| Sonnet 5.5 · low | ۰٫۸۹۹ | ۰٫۷۹۰ | ۰٫۸۶۸ | ۰٫۸۷۱ | ۰٫۸۵۷ | ۰٫۳۷ |
| Sonnet 5.5 · medium | ۰٫۹۰۴ | ۰٫۷۸۰ | ۰٫۸۸۱ | ۰٫۸۶۸ | ۰٫۸۵۸ | ۰٫۳۸ |
| Sonnet 5.5 · high | ۰٫۹۴۴ | ۰٫۸۳۰ | ۰٫۸۶۲ | ۰٫۹۱۶ | ۰٫۸۸۸ | ۰٫۵۹ |

نمره از ۰ تا ۱ است. هزینه برای همه‌ی ۵۴۴ سوال است، با Batch API (نصف قیمت
عادی). کل این مرحله ۴٫۸۳ دلار هزینه داشت.

**مهم‌ترین یافته‌ها:**

- **Opus 5.5 در سطح low بهترین نتیجه را می‌گیرد** و ارزان‌ترین Opus هم هست.
  فکر کردن بیشتر نمره را بالا نبرد.
- **Sonnet 5.5 برای نزدیک شدن به Opus به سطح high نیاز دارد.** Sonnet بدون
  فکر ارزان‌ترین گزینه است: نمره‌ی ۰٫۸۴۵ با ۰٫۳۱ دلار.
- **split چالشی برای همه سخت‌ترین است** و مدل‌ها را بهتر از بقیه از هم جدا
  می‌کند. سخت‌ترین ترک آن «ابهام» است: همه‌ی معناهای «شیر» و «مهر» بدون
  اِعراب، یا تشخیص طعنه.
- **Opus 5.5 فارسیِ تایپ‌شده با کیبورد انگلیسی را گاهی تهدید امنیتی تشخیص
  می‌دهد** و جواب نمی‌دهد (مثل `gxth thdg vh fvhd lk ftvsj` به‌جای «لطفا فایل را
  برای من بفرست»). Sonnet 5.5 به همه‌ی این سوال‌ها جواب داد.
- روی دو split قدیمی (عمومی و سخت) GPT-5.5 هنوز جلوتر است، ولی بخشی از این
  فاصله از یک ایراد امتیازدهی است: شمارش کلمه در سوال‌های قدیمی کلمه‌ی
  نیم‌فاصله‌دار مثل «لامپ‌های» را دو کلمه حساب می‌کند و مدلی را که نیم‌فاصله را
  درست می‌نویسد جریمه می‌کند.

جدول کامل همه‌ی مدل‌ها، نمره‌ی هر ترک و جزئیات در
[`docs/BENCHMARK_REPORT.md`](docs/BENCHMARK_REPORT.md) است (انگلیسی). جدول
leaderboard هم در [`leaderboard/leaderboard.csv`](leaderboard/leaderboard.csv).

## سوال‌ها

۵۵۴ سوال در پنج split:

| split | تعداد | چه چیزی را می‌سنجد |
|---|---:|---|
| `dev` | ۱۰ | نمونه‌ی کوچک برای امتحان اجرا |
| `public_eval` | ۱۴۹ | دانش عمومی، پاسخ کوتاه، خواندن متن، پیروی از دستور، فرهنگ |
| `hard` | ۱۴۵ | نسخه‌ی سخت‌تر: استدلال، ریاضی، خواندن، دستور، فرهنگ |
| `practical` | ۱۵۰ | کارهای روزمره: نوشتن نامه و پیام، ویرایش متن، تاریخ و عدد، استخراج اطلاعات به JSON، تعارف، خلاقیت |
| `challenge` | ۱۰۰ | سوال‌هایی که برای مدل‌های نسل جدید هم سخت بمانند |

نمونه‌هایی از split چالشی:

- **پیش‌فرض غلط:** «چرا فردوسی گلستان را نوشت؟» مدل باید بگوید گلستان از
  سعدی است.
- **جواب فقط از متن:** اگر جواب در متن نیست، مدل باید بگوید «در متن نیامده
  است» و از خودش چیزی نسازد.
- **ابهام:** همه‌ی معناهای «شیر»، «کرم» یا «ملک» بدون اِعراب.
- **دانش زنجیروار:** «رودی که از زیر سی‌وسه‌پل می‌گذرد به کجا می‌ریزد؟» یا
  نسبت‌هایی مثل جاری و باجناق.
- **بازی با کلمه:** جمله‌ای که از آخر به اول همان باشد، توشیح «مهتاب» با
  قافیه، شمردن نقطه‌های یک کلمه.

سوال‌های `practical` و `challenge` تازه‌اند و هنوز باید یک فارسی‌زبان
بازبینی‌شان کند. اگر می‌خواهی کمک کنی، راهنما در
[`CONTRIBUTING_DATASET.md`](CONTRIBUTING_DATASET.md) است.

## امتیازدهی

- **قطعی و بدون داور هوش مصنوعی.** هر جواب با قاعده‌ی مشخص نمره می‌گیرد:
  گزینه‌ی درست، جواب کوتاه با پذیرش نگارش‌های مختلف، شباهت کلمه‌ای، شرط‌های
  قابل‌بررسی (کلمه‌ی لازم یا ممنوع، حرف اول سطرها، قافیه، تعداد کلمه) و
  مقایسه‌ی فیلد به فیلد برای JSON.
- **متن فارسی یکدست می‌شود** پیش از مقایسه: «ي» و «ك» عربی، اعداد فارسی و
  انگلیسی، و نیم‌فاصله.
- **بازه‌ی اطمینان** هر نمره با bootstrap حساب می‌شود.
- **پاسخ مرجع:** در splitهای `practical` و `challenge` هر سوال غیرچندگزینه‌ای
  یک پاسخ مرجع دارد که باید نمره‌ی کامل بگیرد. CI این را بررسی می‌کند تا
  سوالی که جواب درستش نمره نمی‌گیرد وارد دیتاست نشود.

## اجرا

اگر برنامه‌نویس نیستی، از [`START_HERE_FA.md`](START_HERE_FA.md) شروع کن.
خلاصه:

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -e .

# اجرای آزمایشی بدون کلید و بدون هزینه
persian-eval run --model smoke --backend mock \
  --data data/persian_eval_v1.dev.jsonl --output results/smoke.json

# Claude با API خود Anthropic، به‌صورت Batch (نصف قیمت)
export ANTHROPIC_API_KEY=...
python scripts/run_matrix.py --config configs/anthropic_models.json --estimate
python scripts/run_matrix.py --config configs/anthropic_models.json

# هر مدلی از راه OpenRouter با یک کلید
export OPENROUTER_API_KEY=...
python scripts/run_matrix.py --estimate
```

`--estimate` پیش از هر خرجی هزینه را تخمین می‌زند. اگر اجرایی وسط کار قطع
شد، همان دستور را دوباره بزن؛ سوال‌هایی که جواب گرفته‌اند دوباره پرسیده
نمی‌شوند. مدل‌های open-weight را هم می‌شود روی GPU خودت اجرا کرد (backend
`hf`).

## برنامه‌ی بعدی

- بازبینی انسانی سوال‌های `practical` و `challenge`
- اصلاح شمارش کلمه‌های نیم‌فاصله‌دار در سوال‌های قدیمی
- مرحله‌ی دوم: سطح فکر `max` برای Opus و Sonnet، و Claude Fable 5.1
- اجرای GPT-6، Gemini، Grok و DeepSeek از راه OpenRouter
- سوال‌های سخت‌تر برای ترک «جواب فقط از متن»

برنامه‌ی کامل و تخمین هزینه‌ها در [`docs/ROADMAP_FA.md`](docs/ROADMAP_FA.md).
